ARSITEKTUR IMPLEMENTASI
Gunakan arsitektur yang paling sederhana dan aman yang cocok dengan codebase yang sudah ada.
- Utamakan modular monolith untuk MVP.
- Pisahkan worker/background process bila diperlukan untuk market data, strategi, trading simulator, atau notifikasi.
- Gunakan adapter/interface untuk exchange agar penambahan exchange tidak merusak modul inti.
- Gunakan API versioning, misalnya /api/v1.
- Gunakan OpenAPI/Swagger atau dokumentasi kontrak API yang setara.
- Gunakan PostgreSQL untuk data transaksional jika sesuai dengan codebase.
- Gunakan Redis hanya jika benar-benar dibutuhkan untuk cache, session, rate limit, pub/sub, atau job coordination.
- Jangan menambahkan RabbitMQ, TimescaleDB, Go, atau service terpisah hanya demi mengikuti rancangan jika kompleksitasnya belum diperlukan untuk MVP. Jika stack tersebut sudah ada, pertahankan dan integrasikan secara hati-hati.
- Pilih teknologi berdasarkan codebase aktual, bukan berdasarkan asumsi.
- Dokumentasikan setiap penyimpangan dari SDD.

KONTRAK BACKEND
- Semua endpoint harus memiliki validasi input.
- Semua query data pengguna harus dibatasi berdasarkan user_id dari sesi/token yang tervalidasi.
- Endpoint admin harus dilindungi RBAC.
- Error response harus konsisten dan tidak membocorkan secret atau detail internal.
- Endpoint sensitif harus memiliki rate limiting.
- Operasi penting harus idempotent jika memungkinkan.
- Gunakan transaksi database untuk perubahan data yang membutuhkan atomicity.
- Simpan timestamp dan status yang jelas untuk order, trade, bot, dan event.
- Pisahkan status order: pending, accepted, rejected, filled, cancelled, failed sesuai kebutuhan aktual.
- Jangan mengubah kontrak API frontend tanpa memperbarui frontend dan dokumentasi terkait.

PAPER TRADING
Implementasikan simulator yang dapat diuji:
- Saldo virtual awal yang dapat dikonfigurasi sesuai keputusan produk.
- Harga berasal dari data pasar atau fixture test yang jelas.
- Order simulasi tidak pernah memanggil endpoint order riil.
- Perhitungan fee dan slippage harus eksplisit; jika belum diputuskan, gunakan konfigurasi development yang terdokumentasi dan tandai sebagai TBD.
- Validasi saldo, quantity, precision, minimum order, dan status bot.
- Pencatatan order, trade, posisi, saldo, dan PnL.
- Dukungan reset akun simulasi hanya dengan konfirmasi dan audit log.
- Sediakan mode deterministic/mock untuk test agar hasil dapat direproduksi.
- Uji kasus normal dan kasus ekstrem: saldo tidak cukup, harga invalid, koneksi terputus, duplicate event, order ditolak, dan restart worker.

UI/FRONTEND

- Hubungkan mock data ke API nyata secara bertahap.
- Pastikan loading, empty, error, offline, success, dan permission state tersedia.
- Tampilkan status PAPER TRADING secara sangat jelas.
- Jangan menampilkan kontrol live trading sebagai kontrol aktif pada fase ini.

KEAMANAN DAN AUDIT
Periksa minimal:
- Secret leakage.
- .env yang tidak sengaja ter-commit.
- Password hashing.
- Session/token expiry.
- RBAC.
- User data isolation.
- SQL injection, XSS, CSRF sesuai arsitektur.
- CORS dan security headers.
- Rate limiting.
- Audit trail append-only untuk aksi sensitif.
- Log redaction.
- Backup dan restore.
- Dependency vulnerability scan jika tooling tersedia.
- Tidak adanya endpoint live trading yang aktif secara tidak sengaja.

ATURAN EKSEKUSI PER FASE
Jangan mengerjakan seluruh proyek sekaligus. Gunakan urutan berikut:

FASE 0 — DISCOVERY DAN AUDIT
Audit repository, UI, backend, environment, dokumen, dan test. Jangan melakukan refactor besar.

FASE 1 — FOUNDATION
Perbaiki cara menjalankan proyek, environment, database, migration, health check, logging, error handling, dan dokumentasi dasar.

FASE 2 — AUTHENTICATION
Implementasikan login/register/session/RBAC sesuai scope yang sudah disetujui. Tambahkan test keamanan dasar.

FASE 3 — MARKET DATA
Implementasikan adapter data pasar dan fallback/mock fixture untuk test. Tangani rate limit, timeout, retry terbatas, dan kegagalan koneksi.

FASE 4 — PAPER TRADING CORE
Implementasikan simulator, saldo virtual, order, trade, posisi, fee/slippage yang terdokumentasi, dan isolasi paper trading.

FASE 5 — BOT DAN STRATEGY
Implementasikan lifecycle bot, strategi dasar yang disetujui, signal validation, dan risk gate.

FASE 6 — PORTFOLIO DAN DASHBOARD
Hubungkan dashboard UI dengan API nyata, termasuk saldo virtual, PnL, posisi, bot, order, dan status sistem.

FASE 7 — HISTORY, NOTIFICATION, ADMIN
Implementasikan riwayat, notifikasi, audit log, dan admin sesuai scope.

FASE 8 — HARDENING DAN QA
Jalankan test menyeluruh, security checks, error-path testing, restart testing, dan build production.

FASE 9 — LOCAL RELEASE
Pastikan pengguna dapat menjalankan seluruh sistem di MacBook dengan instruksi yang jelas dan bukti test.

FASE 10 — VPS/DOMAIN READINESS
Siapkan dokumentasi dan konfigurasi deployment. Jangan mengaktifkan live trading.
